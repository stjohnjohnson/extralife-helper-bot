## Review Focus

1. A poll captures one session but completes after a reset/new broadcast: reject stale accounting and animations rather than charge the new session (Tasks 3/5).
2. More than 100 gifts or insertions while paging: conditional catch-up must not miss money or announce history on restart (Tasks 1/5).
3. A duplicate initially hides its amount, then reveals it, or contradicts a previously known amount: adjust known money at most once and diagnose conflicts without replay (Task 2).
4. An old companion or delayed image worker survives a clear/upgrade: fail/degrade visibly and never flash stale effects or lose transport (Tasks 4/6).
5. SIGINT/port collision with an existing bot: the runner must clean up only its own temporary files, sockets, and synthetic viewers (Task 7).

### Shared data contracts

All times are integer epoch milliseconds. All money is a nonnegative safe integer number of USD cents. Values described below are validated at boundaries, not asserted by callers.

```js
Donation = { id, participantId, createdAtMs, amountCents }; // amountCents: number | null
CampaignObservation = { observedAtMs, totalCents, goalCents }; // goalCents positive
DonationScan = { participantId, fromMs, throughMs, donations, complete: true };
CelebrationIntent = { sessionId, donationIds, liveTotalCents,
  milestoneCents: null | number, goalReached: boolean };
```

The source emits raw newest-page records to the existing notification path, and normalized complete-window scans to accounting. It never supplies a partial scan as complete. Conflicting or malformed records produce sanitized diagnostic codes without donor names/messages.
