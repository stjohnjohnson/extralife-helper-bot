# Stream Avatars LAN Bridge and Resumable Broadcast Sessions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, or superpowers:subagent-driven-development if the user explicitly selects delegation. Steps use checkbox syntax for tracking. This planning task does not authorize feature implementation.

**Goal:** Implement [#65](https://github.com/stjohnjohnson/extralife-helper-bot/issues/65): an optional authenticated LAN bridge, persistent broadcast continuity, moving-heart preview, and isolated offline rehearsal controlled primarily through Twitch chat.

**Architecture:** A transport-independent broadcast session reducer consumes the existing Twitch viewer monitor's typed observations and persists state atomically. An optional WebSocket service sends validated snapshots and short-lived effects to a Lua companion; a shared rehearsal controller supplies separate simulated state and virtual time through Twitch-admin and local CLI adapters. Lua owns avatar positions, synthetic crowds, and object cleanup.

**Tech Stack:** Node.js 24.x >=24.15.0 <25, CommonJS, Jest 30, ESLint 9, direct locked `ws` dependency, Stream Avatars Lua, and Lua 5.4 for an offline stub harness.

**Spec:** [Foundation design](../../plans/2026-10-08-stream-avatars-foundation-design.md), interpreted within the [approved full design](https://github.com/stjohnjohnson/extralife-helper-bot/blob/codex/stream-avatars-design/docs/plans/2026-10-08-stream-avatars-design.md). PR #69 is open at planning time. This plan can proceed from current `origin/main` without merging that branch.

## Global Constraints

- Node.js 24.x, at least 24.15.0; install locked dependencies with `npm ci`.
- Work on an isolated `codex/` task branch from freshly fetched `origin/main`; preserve other checkouts.
- Default confirmed-offline grace: 900 seconds, configurable. Unknown/error observations are never offline evidence.
- Stable session UUID and original Twitch start survive short offline periods, changed Twitch metadata, companion reconnects, and restarts.
- Loading/recovery/reconnection emits current state only; never replay old transient celebrations.
- Separate production/rehearsal state, donation IDs/totals, and checkpoints. Reset/exit cannot modify live state.
- Admin-only Twitch rehearsal controls; simulated announcements/markers suppressed; physical Hue defaults off with explicit opt-in. Short replies to admin controls are allowed.
- A real successful live observation automatically stops integrated rehearsal and clears synthetic objects/users before production rendering resumes.
- Credential-free local rehearsal remains available without Twitch, Discord, or ExtraLife configuration.
- No themes, real donation celebrations, milestone logic, or time/chapter/finale effects in this issue; reserve interfaces for #66–#68.
- Run complete `npm run lint` and `npm test` before every implementation commit/PR. Retain coverage thresholds: statements/lines 85%, branches/functions 80%.
- Final delivery requires real Linux/LAN/Stream Avatars/OBS evidence, required CI success, and a clean task worktree. Do not merge without instruction.

## Review Focus

- An API outage or a long unobserved bot shutdown must not manufacture a session end: Tasks 1–2 test unknown interruptions and stale offline evidence.
- Corrupt state, failed writes, or aliased rehearsal paths must not lose production progress: Task 1 tests quarantine, atomic failure, and symlink/hard-link aliases.
- A late callback/event from rehearsal must not render after the channel goes live: Tasks 3, 5–6 test rendering generations and stop races.
- Duplicate Twitch messages or an unauthorized admin lookalike must not execute an action twice: Task 6 tests message-ID admission and trusted sender identity.
- Dense crowds, disappearing users, or Lua coroutine boundaries must not leak objects or escape the strip: Task 4 tests movement, caps, expiry, and shared-state ownership; Task 7 proves them on hardware.

Notation below is JSDoc notation, not a TypeScript migration:

- `Mode = 'production' | 'rehearsal'`.
- `Observation = {status:'online'|'offline'|'unknown', observedAtMs:number, streamId?:string, startedAtMs?:number}`; require finite timestamps and valid start <= observation for online. Reject out-of-order observations.
- `SessionState = {schemaVersion:1, mode:Mode, channel:string, revision:number, sessionId:string|null, startedAtMs:number|null, endedAtMs:number|null, latestObservation:Observation|null, offlineSinceMs:number|null, lastOfflineAtMs:number|null, processedDonationIds:string[], liveTotalCents:number, reachedDonationCheckpoints:number[], reachedTimeCheckpoints:number[], chapter:number, campaignGoalReached:boolean, recoveryBaselineMs:number|null}`.
- Initial ledger/checkpoint values: `[]`, `0`, and `false`; preserve populated values on restart. `sessionId` is an application UUID, never the Twitch stream ID. Reserve ledger updates for subsequent issues.
- `Snapshot = {version:1,type:'snapshot',mode:Mode,generation:number,serverNowMs:number,session:SessionState,elapsedMs:number,strip:{x:number,y:number,width:number,height:number},rehearsal:{active:boolean,crowdIds:string[]},features:string[]}`. Foundation features are `['hearts','crowd','session','clock']`; future slices add capabilities rather than pretend controls already work. Future theme/game fields are introduced by #66 and fundraising/checkpoint visual state by #67–#68 under an explicit compatible protocol evolution, not inferred in this foundation.
- `Effect = {version:1,type:'hearts',mode:Mode,generation:number,sessionId:string,id:string,issuedAtMs:number,expiresAtMs:number,durationMs:5000}`. Use real wall time for transport expiry even when rehearsal time jumps.
- Other server messages: `clear` and `crowd` with mode/generation; crowd payload is a bounded desired list of synthetic user IDs. Client messages: `auth` (`version`, `token`), `ready` (capabilities/resolution), `heartbeat`, and sanitized `diagnostic` with allowlisted code. No remote executable text, script paths, or arbitrary assets.
