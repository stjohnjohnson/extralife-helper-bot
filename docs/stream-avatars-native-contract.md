# Stream Avatars renderer contract

The issue #66 renderer is based on the installed macOS Steam build 25169902 (AppID 665300). The displayed app version was not obtained. Static inspection and synthetic native component checks establish signatures and collection conversion; they do not establish graphical acceptance. No installed DLLs, decompiled implementation, private avatar artwork, or application settings are included in this repository.

## Host boundary

- `app.createGameObject()`, `applyImage(object, imageName)`, `object.setPosition(x, y)`, and `object.setScale(x, y)` are exposed. Loading yields; a native failure can escape Lua `pcall`, and a callback may never return. Workers isolate transport and deadlines. All pending images remain at scale zero. At most 100 unresolved loads are retained until host reload; failed world components are skipped independently.
- `object.image.anchor("center", true)` sets the camera center; the renderer subsequently assigns its explicit position. `object.image.sorting(order, layer)` accepts `foreground`, `afterForeground`, `behindBackground`, and `background`. The candidate renderer requests backdrop `behindBackground`/0 and props `background`/1. The global visual layer order remains unverified.
- Script image metadata determines native sprite extent: `frameWidth * metadata.scale * objectScaleX` (and equivalent height). The installed loader uses sprite PPU `1 / metadata.scale` and the metadata origin as sprite pivot. Theme packages explicitly use metadata scale 1 and center pivot (0.5, 0.5). Image-space anchors point down; center Y is `baselineOffset + anchorY - height/2` above the native bottom.
- `app.convertPercentToPosition(x,y)` follows the installed screen formula `(x * screenWidth/2 - screenWidth/4, y * screenHeight/2)`. At 1920×1080 it gives bounds (-480,0)..(480,540). OBS transforms and actual destination crop remain unmeasured. Worlds use native width / 1920 uniformly: four whole 480×64 tiles fit even when native width is fractional. There is no exposed clipping API; non-1920 reference profiles are rejected and would need separately derived tail images.
- `object.text.setText(string)`, `object.text.setSize(int)`, and object position are implemented. Text sorting, font selection, outline, and color methods are empty. No exposed measurement or rich-text-disable API exists. Captions remove angle brackets and ASCII controls and conservatively truncate at 48 Unicode code points, using an ellipsis. This is input handling, not proven glyph fit, font coverage, or plain-text graphics.
- `user.runCommand("jump", true)` enters the installed native jump command path without teleporting or changing movement bounds. Native permissions, cooldowns, and actual grounded behavior remain unverified. Only a current, nonexpired, unseen entrance event invokes it; snapshots do not.
- Under the installed `LuaScriptFunctions.AssignDataFunctions` setup, CLR `List<string>` and `List<User>` become 1-based Lua tables; user elements remain userdata. Unregistered `Dictionary<string,string>` becomes a Lua table with string keys. The harness models these observed conversions and only the APIs used above.

## Ownership and packaging

Hearts, lasting theme objects, entrance captions, and the reserved empty chapter owner have independent lifetimes. A shared-theme game change preserves scenery positions while replacing the entrance. Session, mode, clear, and disconnect fence all owners. Theme revision or theme ID changes cancel the theme loader owner and current entrance, preserving hearts. Caption host failures destroy only the failed caption and preserve the other owners. Resizing recomputes positions and scale without reloading artwork; insufficient height hides the world until bounds recover.

`buildThemeCatalog({manifest, previewOnly:true})` accepts an explicit local candidate manifest, validates IDs, checksums, safe relative export paths, and geometry, and derives a 64-hex semantic revision without machine paths or local review labels. `buildThemeLayout({theme,packRevision,referenceWidth:1920})` and the artwork gallery share prop placement. `buildPackage({themeManifest,themeAssetsDir,previewOnly:true})` verifies PNG bytes and embeds allowlisted IDs/geometry. A candidate package renders artwork only in active rehearsal. The default package has no world assets. Arbitrary approval flags cannot enable production promotion: the separately reviewed selected-artifact/native-proof gate must supply that capability in the packaging task.

The Lua harness proves simulated owner behavior and exact host calls, including red/green and behavioral mutations. Static/component proof remains separate from graphical proof. Native 0/20/100 viewer previews, literal seams, transparency, image ordering, caption fit, actual jump behavior, negative/resized bounds, and OBS acceptance remain pending. Local candidate compositing must be labeled simulated; it is not native graphical evidence.


## Temporary head hats and operator fitting (Task 5)

The reserved gear set is `sa_helper_theme_hats`, used exclusively by this integration for the twelve allowlisted hats/helmets. Native sets have neither owner tokens nor a universal head slot. The companion writes only `user.setTemporaryGear(set,piece,30)`, renews the current tracked piece after ten wall-clock seconds, and conditionally shortens it to one second on release. Native gear reads occur only immediately before possible writes, because the getter logs every read. If the current avatar no longer permits the namespace, native WearGear silently rejects release too; the original finite lease remains the restoration fallback. It skips occupied effective values and never calls persistent gear setters, saved-user writes, or global cosmetic clears. A foreign feature using the exact reserved set and piece is indistinguishable; exclusive reservation is required. Other sets, characters, palettes and latest saved choices remain independent.

Installed `LuaScriptFunctions.MainGetUsers` enumerates every entry in `SA_Game.access.activeCharacters` without a role or count filter; the broadcaster is eligible whenever present in that active-character collection. `User.CreateUser` returns a fresh wrapper each time. Ownership therefore uses stable user IDs and effective pieces, never wrapper identity or captured saved appearance. Installed registration converts dictionaries/lists to ordinary Lua tables (the earlier twelve native assertions). The synthetic harness covers 1,002 active users including a caster, finite restoration, new joins, avatar changes, primary/alternate availability and conditional release. Native reconciliation is capped at 32 users per 50ms render tick; collection enumeration/sorting remains O(N). Tested population is not an unlimited-capacity guarantee.

`SA_MoonSharp.SA_Script.InitializeScript` constructs `new Script()` without a core-module preset or later restriction. A new probe uses that same installed constructor and assembly: `os.time()` is callable, returns fractional numeric wall-clock seconds, and agrees with UTC within two seconds. Native expiry uses `DateTime.Now`; the script's `SA_GetDeltaTime` uses scaled Unity `Time.deltaTime`. Gear leases use floored wall time conservatively, so a paused game cannot create ownership of a restored identical saved hat. Missing, invalid or backward clocks stop renewal and release until reload; existing leases expire naturally. The new probe touches no production settings or users; Unity's resource-loader ECall warning outside Unity remains a limitation. This clock/component evidence does not establish the graphical update loop.

`npm run sa:fit -- --settings FILE --plan NEW_FILE [--overrides FILE]` is dry-run only. It reads the native settings root `avatarData`, emits only avatar keys/dimensions/counts, own-set frame pivots, source checksum and a six-theme `gearCompatibility` map. Both outputs explicitly remain provisional with `graphicsVerified:false`. Starter coordinates `(0, 0.75 * canvasHeight)` are review-only; uniform canvas dimensions do not prove head locations. Override structure is `{avatarKey:{x,y,animations:{idle:{x,y,frames:{"0":{x,y}}}}}}`, with zero-based native frame indexes. Unknown/malformed geometry and existing own-set permissions/pivots are skipped intact.

After reviewing a plan, `--apply --app-closed` explicitly confirms the app is closed, requires the unchanged source checksum, verifies a private mode0600 byte-for-byte backup, validates every eligible frame and coordinate, verifies that only own-set `CanUseGear` permissions and `gearPivot` points changed, then fsyncs and atomically replaces the settings. Parent directory sync is used on POSIX; Windows file sync/rename is supported by Node but has not been exercised here. Node24 raw JSON numeric tokens preserve unrelated native Int64/decimal precision during serialization. No `userrecords`, saved selections, credentials or unrelated settings are semantically changed or printed. Apply tests use synthetic temporary files exclusively; the operator's private settings have not been applied.

`gear-compatibility.json` intentionally contains no approved avatar entries. Explicit candidate `buildThemeCatalog`/`buildPackage` calls accept a provisional `gearCompatibility` map only with `previewOnly:true` and a candidate manifest; runtime additionally requires active rehearsal and the exact catalog revision. The revision binds hat hashes/geometry and fitting semantics. Packages contain fresh own-set gear PNGs/metadata, with an empty native `avatar` root. Gear-only import does not install avatar permissions or pivots, so separate fitting/setup and native acceptance are required. No private avatar metadata is bundled and no candidate approval flag enables production.

Pending graphical acceptance: import the fresh namespace, manually review permissions and every intended left/right idle/walk-or-run/jump/sit fit on representative small/large enabled avatars; verify actual 30s expiry, 10s renewal and 1s conditional release while saved hats/palettes/avatars change; neutral/theme transitions, late arrival, leave/rejoin, disconnect/reconnect, disable, F5 and script failure; foreign-set coexistence and occupied reserved-set fallback. Record tested avatar keys/variants and checksums. These checks remain pending, and no native fitted avatar or graphical restoration is claimed.


## Installed caption Unicode correction

Standard Lua5.2/5.4 strings contain UTF8 bytes; installed MoonSharp strings contain .NET UTF16 units. Native `string.byte` is lossy for non-ASCII text and native pattern classes cast code units to low bytes. The earlier pattern-based sanitizer therefore dropped some CJK characters and split emoji surrogates despite passing standard Lua tests. The companion now detects installed `string.unicode`, reads its numeric UTF16 units, keeps valid surrogate pairs as one scalar and drops isolated surrogates. Standard Lua uses a validated UTF8 decoder instead. Both remove only numeric ASCII controls/DEL and angle brackets, preserving the existing48-scalar bound with an ellipsis for longer names.

An installed MoonSharp probe used the application's exact `new Script()` constructor, `Options.UseLuaErrorLocations=true` and actual `AssignDataFunctions(0)` registration. It extracted the unchanged shipping caption function and checked18 cases against independent .NET Rune.DecodeFromUtf16 expectations: full CJK, accented text, mixed text, emoji, low-byte CJK control/angle collisions, invalid surrogate units, U+FFFD and48/49-scalar boundaries all passed, with zero unpaired output surrogates. Seventy emoji produce47 intact emoji plus an ellipsis. Shipping function SHA256: `dfae1eabb951f2ed8891591761dd6b815b01ad1b4ca2fdf481f5c1e1086a4818`. This is actual interpreter behavior; TMP fonts, graphical glyph fit and width measurement still require native acceptance.
