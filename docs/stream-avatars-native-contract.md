# Stream Avatars renderer contract

The renderer behavior probes below were performed on macOS Steam build **25169902** (AppID 665300) and remain historical evidence. The current installed build is **25831299**; its changed core assembly requires fresh behavior acceptance. The displayed app version was not obtained. Static inspection and synthetic native component checks establish only the stated signatures and conversions. No installed DLLs, decompiled implementation, private avatar artwork, or application settings are included in this repository.

## Historical host boundary — build 25169902

- `app.createGameObject()`, `applyImage(object, imageName)`, `object.setPosition(x, y)`, and `object.setScale(x, y)` are exposed. Loading yields; a native failure can escape Lua `pcall`, and a callback may never return. Workers isolate transport and deadlines. All pending images remain at scale zero. At most 100 unresolved loads are retained until host reload; failed world components are skipped independently.
- `object.image.anchor("center", true)` sets the camera center; the renderer subsequently assigns its explicit position. `object.image.sorting(order, layer)` accepts `foreground`, `afterForeground`, `behindBackground`, and `background`. The historical candidate requested backdrop `behindBackground`/0 and props `background`/1. This was superseded by the current visible-overlay contract below.
- Script image metadata determines native sprite extent: `frameWidth * metadata.scale * objectScaleX` (and equivalent height). The build-25169902 loader uses sprite PPU `1 / metadata.scale` and the metadata origin as sprite pivot. Theme packages explicitly use metadata scale 1 and center pivot (0.5, 0.5). Image-space anchors point down; center Y is `baselineOffset + anchorY - height/2` above the native bottom.
- `app.convertPercentToPosition(x,y)` uses the screen formula inspected on build 25169902 `(x * screenWidth/2 - screenWidth/4, y * screenHeight/2)`. At 1920×1080 it gives bounds (-480,0)..(480,540). OBS transforms and actual destination crop remain unmeasured. Worlds use native width / 1920 uniformly: four whole 480×64 tiles fit even when native width is fractional. There is no exposed clipping API; non-1920 reference profiles are rejected and would need separately derived tail images.
- `object.text.setText(string)`, `object.text.setSize(int)`, and object position are implemented. Text sorting, font selection, outline, and color methods are empty. No exposed measurement or rich-text-disable API exists. The historical title renderer removed angle brackets/ASCII controls and truncated at 48 Unicode code points. Game/title text rendering and that sanitizer were removed at the user's request on 2026-10-12; donation captions use the existing bitmap images.
- The companion uses `user.runCommand("!{cmd:jump}", true)` for the quiet native jump command. Native permissions, cooldowns, and actual grounded behavior remain unverified. Only a current, nonexpired, unseen entrance event invokes it; snapshots do not.
- Under the build-25169902 `LuaScriptFunctions.AssignDataFunctions` setup, CLR `List<string>` and `List<User>` become 1-based Lua tables; user elements remain userdata. Unregistered `Dictionary<string,string>` becomes a Lua table with string keys. The harness models these observed conversions and only the APIs used above.

## Ownership and packaging

The connection indicator uses `LuaApp.getStreamerUser()` to obtain the native host avatar. A read-only signature probe on installed build 25831299 confirms a `User` return type. `User.isActive` and `User.streamer` have Boolean return types; `User.id` returns a string. The [official user documentation](https://docs.streamavatars.com/lua-scripting-api/api-reference-and-tips/classes/user) also exposes these properties. These signatures do not establish graphical placement. The Lua harness checks host absence, movement, authentication, stale wall-clock heartbeats and image failure isolation. The status owner is independent of celebration and scenery cleanup. Native import and visual placement remain operator acceptance checks.

Hearts, lasting theme objects, pending entrance jumps, and the reserved empty chapter owner have independent lifetimes. A shared-theme game change preserves scenery positions while replacing the entrance. Session, mode, clear, and disconnect fence all owners. Theme revision or theme ID changes cancel the theme loader owner and current entrance, preserving hearts. An entrance allocates no native text or scene object. Its pending jump is consumed once, expires after six seconds if rendering is delayed, and is canceled on a game/scope switch. Resizing recomputes positions and scale without reloading artwork; insufficient height hides the world until bounds recover.

`buildThemeCatalog({manifest, previewOnly:true})` accepts an explicit local candidate manifest, validates IDs, checksums, safe relative export paths, and geometry, and derives a 64-hex semantic revision without machine paths or local review labels. `buildThemeLayout({theme,packRevision,referenceWidth:1920})` and the artwork gallery share prop placement. `buildPackage({themeManifest,themeAssetsDir,previewOnly:true})` verifies PNG bytes and embeds allowlisted IDs/geometry. A candidate package is admitted only in active integration preview. The default package includes the checked-in user-reviewed scenery for all six themes. Only its trusted repository path receives bundled-art admission; external arbitrary approval flags cannot bypass the selected-artifact/native-proof gate. Every image, geometry and catalog hash is still validated. Bundled provenance claims the actual local review, not fabricated per-image native evidence.

The Lua harness proves simulated owner behavior and exact host calls, including red/green and behavioral mutations. Static/component proof remains separate from graphical proof. Native 0/20/100 viewer previews, literal seams, transparency, image ordering, actual jump behavior, negative/resized bounds, and OBS acceptance remain pending. Local candidate compositing must be labeled simulated; it is not native graphical evidence.

## Historical caption Unicode correction — build 25169902

The title renderer and its sanitizer are retired as of 2026-10-12. The following probes describe the former implementation and are not current caption requirements.

Standard Lua5.2/5.4 strings contain UTF8 bytes; installed MoonSharp strings contain .NET UTF16 units. Native `string.byte` is lossy for non-ASCII text and native pattern classes cast code units to low bytes. The earlier pattern-based sanitizer therefore dropped some CJK characters and split emoji surrogates despite passing standard Lua tests. The companion now detects installed `string.unicode`, reads its numeric UTF16 units, keeps valid surrogate pairs as one scalar and drops isolated surrogates. Standard Lua uses a validated UTF8 decoder instead. Both remove only numeric ASCII controls/DEL and angle brackets, preserving the existing48-scalar bound with an ellipsis for longer names.

The build-25169902 MoonSharp probe used the application's exact `new Script()` constructor, `Options.UseLuaErrorLocations=true` and actual `AssignDataFunctions(0)` registration. It extracted the unchanged shipping caption function and checked18 cases against independent .NET Rune.DecodeFromUtf16 expectations: full CJK, accented text, mixed text, emoji, low-byte CJK control/angle collisions, invalid surrogate units, U+FFFD and48/49-scalar boundaries all passed, with zero unpaired output surrogates. Seventy emoji produce47 intact emoji plus an ellipsis. Shipping function SHA256: `dfae1eabb951f2ed8891591761dd6b815b01ad1b4ca2fdf481f5c1e1086a4818`. This is actual interpreter behavior; TMP fonts, graphical glyph fit and width measurement still require native acceptance.

## Current build 25831299: visible overlay and bounded failure reasons

Fresh static inspection of the current core DLL confirms the same image sorting, position and scale methods. The installed `globalgamemanagers` sorting list places `behindBackground` at index 1, `background` at index 2 and `Characters` at index 8. The companion now requests `background`/1 for backdrop tiles and `background`/2 for props. This puts the continuous overlay above a native background sprite at `background`/0, with props above its backdrop and both below characters. `behindBackground` is a valid native layer, but it explicitly permits native backgrounds to cover the overlay. This ordering contract and its regression are not graphical acceptance of a particular installed scene.

The current native loader defaults zero frame dimensions to the actual texture dimensions, creates sprite frames with the configured center pivot and PPU `1 / metadata.scale`, and enables the renderer before playback. Package scale 1 and the existing placement geometry remain unchanged. No texture, catalog, pivot or PNG change is required for this ordering correction.

A position, sorting or scale failure skips only the affected world component, preserving other tiles, props, pending entrance jumps and hearts. Image failures/timeouts retain `missing-theme-image`; component placement failures use `theme-render-error`. Retired cosmetic diagnostic codes are rejected. Each active world failure reason is limited to one diagnostic per 30 seconds, independently of the other reasons and across theme reloads. Packets contain only protocol version, type and the allowlisted code; no native exception, image path or private user identifier is sent.

Regression coverage includes a modeled native background occluder, each of position/sorting/scale failures, preservation of unrelated owners, ignored legacy gear metadata, per-code rate limits and rejection of diagnostic metadata. Native visual acceptance and literal tile seams remain separate checks.
