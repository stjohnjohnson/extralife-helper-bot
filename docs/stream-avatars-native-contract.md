# Stream Avatars renderer contract

The issue #66 renderer is based on the installed macOS Steam build 25169902 (AppID 665300). The displayed app version was not obtained. Static inspection and synthetic native component checks establish signatures and collection conversion; they do not establish graphical acceptance. No installed DLLs, decompiled implementation, private avatar artwork, or application settings are included in this repository.

## Host boundary

- `app.createGameObject()`, `applyImage(object, imageName)`, `object.setPosition(x, y)`, and `object.setScale(x, y)` are exposed. Loading yields; a native failure can escape Lua `pcall`, and a callback may never return. Workers isolate transport and deadlines. All pending images remain at scale zero. At most 100 unresolved loads are retained until host reload; failed world components are skipped independently.
- `object.image.anchor("center", true)` sets the camera center; the renderer subsequently assigns its explicit position. `object.image.sorting(order, layer)` accepts `foreground`, `afterForeground`, `behindBackground`, and `background`. The candidate renderer requests backdrop `behindBackground`/0 and props `background`/1. The global visual layer order remains unverified.
- Script image metadata determines native sprite extent: `frameWidth * metadata.scale * objectScaleX` (and equivalent height). The installed loader uses sprite PPU `1 / metadata.scale` and the metadata origin as sprite pivot. Theme packages explicitly use metadata scale 1 and center pivot (0.5, 0.5). Image-space anchors point down; center Y is `baselineOffset + anchorY - height/2` above the native bottom.
- `app.convertPercentToPosition(x,y)` follows the installed screen formula `(x * screenWidth/2 - screenWidth/4, y * screenHeight/2)`. At 1920×1080 it gives bounds (-480,0)..(480,540). OBS transforms and actual destination crop remain unmeasured. Worlds use native width / 1920 uniformly: four whole 480×64 tiles fit even when native width is fractional. There is no exposed clipping API; non-1920 reference profiles are rejected and would need separately derived tail images.
- `object.text.setText(string)`, `object.text.setSize(int)`, and object position are implemented. Text sorting, font selection, outline, and color methods are empty. No exposed measurement or rich-text-disable API exists. Captions remove angle brackets and ASCII controls and conservatively truncate at 48 Unicode code points, using an ellipsis. This is input handling, not proven glyph fit, font coverage, or plain-text graphics.
- `user.runCommand("jump", true)` enters the installed native jump command path without teleporting or changing movement bounds. Native permissions, cooldowns, and actual grounded behavior remain unverified. Only a current, nonexpired, unseen entrance event invokes it; snapshots do not.
- Under the installed `LuaScriptFunctions.AssignDataFunctions` setup, CLR `List<string>` and `List<User>` become 1-based Lua tables; user elements remain userdata. Unregistered `Dictionary<string,string>` becomes a Lua table with string keys. The harness models these observed conversions and only the APIs used above.

## Ownership and packaging

Hearts, lasting theme objects, entrance captions, and the reserved empty chapter owner have independent lifetimes. A shared-theme game change preserves scenery positions while replacing the entrance. Session, mode, clear, and disconnect fence all owners. Theme revision or theme ID changes cancel the theme loader owner and current entrance, preserving hearts. Caption host failures destroy only the failed caption and preserve the other owners. Resizing recomputes positions and scale without reloading artwork; insufficient height hides the world until bounds recover.

`buildThemeCatalog({manifest, previewOnly:true})` accepts an explicit local candidate manifest, validates IDs, checksums, safe relative export paths, and geometry, and derives a 64-hex semantic revision without machine paths or local review labels. `buildThemeLayout({theme,packRevision,referenceWidth:1920})` and the artwork gallery share prop placement. `buildPackage({themeManifest,themeAssetsDir,previewOnly:true})` verifies PNG bytes and embeds allowlisted IDs/geometry. A candidate package renders artwork only in active rehearsal. The default package has no world assets. Arbitrary approval flags cannot enable production promotion: the separately reviewed selected-artifact/native-proof gate must supply that capability in the packaging task.

The Lua harness proves simulated owner behavior and exact host calls, including red/green and behavioral mutations. Static/component proof remains separate from graphical proof. Native 0/20/100 viewer previews, literal seams, transparency, image ordering, caption fit, actual jump behavior, negative/resized bounds, and OBS acceptance remain pending. Local candidate compositing must be labeled simulated; it is not native graphical evidence.
